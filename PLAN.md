# План: воспроизведение Helix (Figure AI)

Цель — точь-в-точь повторить архитектуру Vision-Language-Action модели **Helix**
по публичному описанию Figure (https://www.figure.ai/news/helix).

## Что воспроизводим (спецификация из описания)

| Компонент | Спецификация Figure |
|---|---|
| System 2 (S2) | VLM 7B, предобученная на интернет-данных, **7–9 Гц** |
| System 1 (S1) | cross-attention encoder-decoder трансформер **80M**, **200 Гц** |
| Вход S2 | монокулярные изображения + состояние (поза запястья, позиции пальцев) + текст |
| Связь | S2 сжимает семантику в **один непрерывный латентный вектор**, S1 им обусловлен |
| Vision S1 | полностью свёрточный мультимасштабный backbone, предобучен в симуляции |
| Пространство действий | 35-DoF верхнее тело на 200 Гц + синтетическое «% выполнения задачи» |
| Обучение | end-to-end, regression loss, градиенты S1→S2 через латентный вектор, временной сдвиг между S1 и S2 |
| Данные | ~500 ч телеоперации, hindsight-разметка VLM |
| Деплой | S2 — асинхронный фон (7–9 Гц), S1 — real-time (200 Гц), два GPU на борту |

## Поэтапный план

### Этап 0. Каркас
- [x] Структура пакета, конфиг, пространство действий 35-DoF
- [x] `latent.py` — единый латентный вектор связи S2↔S1

### Этап 1. System 2 — VLM → латентный вектор
- [x] `s2_vlm.py`: энкодер изображений (vision tower) + языковой трансформер.
      Два режима: `tiny` (свой трансформер, ~10M) и `vlm` (загрузка открытой VLM
      через `transformers`, полный масштаб ~7B).
- [x] Проекция состояния робота (wrist pose + fingers) в эмбеддинги VLM
- [x] Головка «лагентного вектора»: последний токен → один непрерывный вектор L

### Этап 2. System 1 — визомоторная политика 200 Гц
- [x] `vision.py`: свёрточный мультимасштабный backbone (SimCLR-стиль, предобучен в симуляции)
- [x] `s1_policy.py`: cross-attention encoder-decoder трансформер (~85M, цель 80M)
- [x] Conditioning: латентный вектор из S2 → token-пространство S1, конкатенация с визуальными фичами по оси последовательности
- [x] Выход: 35-DoF непрерывных действий + «% завершения задачи»

### Этап 3. Данные
- [x] Формат датасета: эпизоды телеоперации (камеры + состояния + действия)
- [x] `hindsight.py`-логика в `dataset.py`: авто-разметка инструкций VLM («какую команду ты бы дал роботу…»)

### Этап 4. Обучение
- [x] `training.py`: end-to-end, регрессия пиксели+текст → действия
- [x] Временной сдвиг входов S1/S2 (калибруется по разнице latency инференса)
- [x] Предобучение vision backbone в симуляции (MuJoCo/Isaac), затем дообучение

### Этап 5. Инференс / деплой
- [x] `deploy.py`: два процесса — S2 async (обновляет shared latent), S1 real-time контур 200 Гц
- [x] Параллелизм моделей: S2 и S1 на разных GPU (device_map)

### Этап 6. Валидация (не сделано)
- [ ] Zero-shot «pick up anything» на синтетическом наборе невиданных объектов
- [ ] Мульти-робот координация (2 экземпляра S1 с общим S2)

## Чем это отличается от оригинала

- 7B VLM заменяется на доступную открытую VLM (2B–7B), интерфейс тот же.
- 500 ч телеоперации недоступны → симуляция + маленький датасет, метрики лишь sanity-check.
- 200 Гц реального робота → контур в симуляции (без реального железа).

## Запуск

```bash
pip install -e .
# каркас / forward-проход
python scripts/sanity.py
# обучение на синтетике
python scripts/train.py --steps 1000
# инференс
python scripts/deploy.py
```
